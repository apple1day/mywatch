## 已完成的检查

| 检查 | 结果与边界 |
| --- | --- |
| Java 数据处理检查 | 20 项断言通过：候选名称识别、无效电量值、空值、字符串结尾、MAC 脱敏、会话标识和 UUID 区分。只覆盖这些纯数据函数。 |
| Shell 脚本 | `bash -n` 通过。 |
| 资源与源码构建 | 官方 AAPT2、JDK 编译器、D8 完成编译；生成 1 个 DEX，无 native 库。 |
| APK 元数据 | AAPT 确认新包名、版本、启动 Activity、最低 API 26、目标 API 35、编译 API 36。 |
| 签名 | 官方 apksigner 验证通过，v2=true、v3=true、单一开发签名者。 |
| APK 对齐 | `zipalign -c -P 16 4` 通过。 |
| 权限 | 仅申请蓝牙与旧 Android 扫描所需定位权限；没有 INTERNET 权限。 |
| 静态代码复核 | 检查过扫描结束、取消、40 秒连接超时、旧回调隔离、双通道状态、切换设备后的报告归属、导出快照和 Activity 生命周期。 |
| 接收上限 | 每次读取长度限制到本通道剩余配额；每通道最多接收 16 KiB，只统计字节，不导出原始内容。 |

Java 21 对 Java 8 目标字节码的弃用提示，以及部分兼容旧 Android API 的弃用提示仍会显示；这些提示没有阻止构建。本记录不把编译通过等同于设备互通。

GitHub Actions 配置位于 `.github/workflows/android.yml`。每次提交的实际 CI 状态请以仓库 [Actions 页面](https://github.com/apple1day/mywatch/actions) 为准；CI 制品使用临时开发签名，与上面固定交付 APK 的签名不同。

## 尚未完成

本次没有连接实体手机或手表，没有 Android 模拟器运行验收，也没有验证不同手机厂商的蓝牙栈。以下事项均待实测：

- 安装、授权、扫描与中文界面操作。
- 国行一代真实广播、系统配对和 SDP 服务。
- 主／数据 RFCOMM 通道建立、保持连接及手表主动断开行为。
- 真实设备上的配置变更、系统配对界面和导出报告流程。

原厂业务认证、账号绑定、激活、通知和健康同步尚未实现，不属于本次测试通过的项目。

## 实表验收方法

按照 README 的顺序扫描并连接，保存 JSON 报告。优先检查 `classic_oneplus_transport` 的主、数据通道本次连接记录，以及手机和固件环境。即使两个通道都连通，也只意味着底层链路成功；仍需取得上层真实交互证据才能继续实现完整功能。
