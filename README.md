# 一代手表连接 · OnePlus Watch Link

面向国行 OnePlus Watch 一代的独立安卓**连接验证版**，当前版本 `0.1.0`。

**已实现经典蓝牙双通道连接检测；尚未实现原厂业务绑定、通知、健康数据同步、表盘或固件升级。尚未完成实体手表验收。**

## 下载并测试

[下载 0.1.0 测试 APK](https://github.com/apple1day/mywatch/raw/refs/heads/main/releases/v0.1.0/OnePlus-Watch-Link-0.1.0.apk)

- 应用名称：一代手表连接。
- 包名：`com.anxiong.watchlink`，可以与欢太健康并存。
- Android 8.0（API 26）及以上；需手机蓝牙能力。本版没有 native 库架构限制，也没有手机品牌判断。
- 编译 SDK 36，目标 SDK 35。
- 使用独立开发证书签名；申请附近设备权限，Android 8–11 扫描还需要定位权限和系统定位开关。
- 应用没有联网权限，不要求 OPPO 账号；这些条件仅描述本验证版，不能据此认定完整原厂功能已经脱离账号服务。

### 建议的测试顺序

1. 保留原有应用数据和绑定，让手表亮屏并靠近手机。
2. 打开应用，授权附近设备；点击 **扫描一代手表 · 经典蓝牙**，或查看 **系统已配对**。
3. 选择 `OnePlus Watch` 开头的设备。名称只是候选线索；没有找到时可以显示其他设备。
4. 点击 **连接一代数据通道**，留意手机与手表的系统配对提示。主通道连接成功后，应用等待约 1 秒再连接数据通道。
5. 查看结果并点击 **导出报告**，保存 JSON。报告可以上传回当前聊天，结合真实手机、固件与连接状态继续开发。

若系统配对界面使本应用进入后台，连接可能按前台策略被释放；返回后再次点击连接即可。为了避免与原配 App 同时占用连接，测试时可先退出其运行界面／结束其进程；不需要为本验证版清除数据、解绑或恢复手表出厂设置。

## 已实现的范围

| 功能 | 状态 |
| --- | --- |
| 经典蓝牙发现、系统已配对设备列表、系统配对请求 | 已实现，待手机与手表实测 |
| 一代 secure RFCOMM 主／数据双通道 | 已按上传 APK 的静态调用链实现，待手表实测 |
| 主通道后约 1 秒建立数据通道 | 已实现 |
| 被动接收与字节统计 | 已实现；每通道最多 16 KiB，原始内容不写入报告 |
| 经典蓝牙 SDP 服务查询 | 已实现 |
| BLE 扫描、GATT 服务发现、标准电量／设备信息读取 | 备用诊断；不作为一代主通道的成功标准 |
| 本地 JSON 报告 | 已实现；完整蓝牙地址脱敏，包含手机型号与版本、选中设备名、状态和服务 UUID |
| 原厂认证、账号绑定、激活、通知和健康同步 | 未实现 |
| 实体手表与多品牌手机验收 | 未完成 |

**判读结果：** 系统配对、RFCOMM 通道建立、原厂绑定、健康同步分别是不同阶段。界面与报告会分别标注，不会用“蓝牙已连接”代替“已恢复所有功能”。手表不返回被动数据或主动断开，也不足以单独判断不兼容。

仅在前台保留连接。进入后台时关闭扫描与 Socket/GATT；返回后可手动重连。报告导出时先截取当前状态，再打开系统保存器。

## 为什么使用经典蓝牙

对用户上传的 `com.heytap.health` 版本 `4.22.11_8c76bdd_250530` 做静态分析后，找到一代设备分类通向经典蓝牙 `BRClientDevice` 的调用链：

| 通道 | 服务 UUID |
| --- | --- |
| 命令 | `db764ac8-4b08-7f25-aafe-59d03c27bae3` |
| 数据 | `db764ac8-4b08-7f25-aafe-59d03c27bae4` |

原实现使用公开 Android API `createRfcommSocketToServiceRecord()`。本项目仅依据接口和协议标识重新实现链路验证；不包含原 APK、原厂二进制库、账号凭据或反编译源文件。

详细证据、限制和下一阶段任务见 [APK 分析记录](docs/APK_ANALYSIS.md) 与 [验收记录](docs/VALIDATION.md)。

## 本地构建

需要：Python 3、含 `jdk.compiler` 的 Java 17+、Android SDK Platform 36 和 Build-Tools 36.0.0。可从 Android Studio 的 SDK Manager 安装这两个 SDK 组件。

在仓库根目录运行：

```bash
bash tools/test-profile.sh
bash tools/build-apk.sh
```

脚本使用 AAPT2 → javac → D8 → zipalign → apksigner，无需 Gradle。输出位于 `dist/OnePlus-Watch-Link-0.1.0.apk`。

Mac 默认查找 `$HOME/Library/Android/sdk`。也可以明确指定已安装的工具：

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"
bash tools/build-apk.sh
```

非标准目录可通过 `ANDROID_JAR`、`ANDROID_BUILD_TOOLS` 指定。首次本地构建会在 `.dev-signing/` 创建开发签名，后续复用；此目录被 Git 忽略。自己重新生成的证书与仓库测试 APK 的证书不同，Android 不允许不同签名直接覆盖同包应用。

GitHub Actions 自动运行数据处理检查和 APK 编译、签名校验。CI 制品使用每次运行新建的开发证书，适合独立测试；仓库 `releases/v0.1.0/` 保存本次交付 APK 及其校验值。
